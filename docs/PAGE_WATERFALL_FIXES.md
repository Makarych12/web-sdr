# Мобильный VFO, S-meter, прокрутка и контраст waterfall

- Оба существующих валкодера оставлены на месте. Основной имеет desktop-диаметр 164 px и одинаковые лицевую панель, указатель и подпись на всех ширинах. На узкой сетке он центрируется в собственной строке без масштабирования. Нижний остаётся 86 px.
- Существующие фиксированные строки S-meter усилены изоляцией размеров (`contain: layout size`), фиксированной шириной всей строки показаний и её отдельных частей. Перенос запрещён, цифры табличные. Высота 88 px до 820 px и 76 px на desktop; границы показаний не могут расширять сетку приёмника.
- Обычное колесо над спектральными canvas больше не перехватывается; zoom выполняется только с Ctrl. Waterfall разрешает нативный `pan-y`. До определения направления одного пальца настройка не меняется; вертикальный жест, `pointercancel` и прокрутка отменяют отложенные действия и завершающее касание. Горизонтальные жесты, tap, VFO и фильтр, клавиатура и pinch сохранены.
- Историческое исправление контраста найдено в `7f3a7f2c86c14dbb4b5bf4b4f3c22d258f89c9b7`. Его нормализация сохранилась, но после перехода к сохранению истории при `setView` больше не переоценивался шум нового диапазона. Восстановлен сброс только оценки noise floor на новом обзоре, без удаления строк истории. Первая новая строка сразу использует шум нового диапазона. Waterfall и его история непрозрачны, alpha=1, композиция source-over, фон тёмный. Сглаживание canvas и CSS отключено; CSS-высота соответствует контейнеру. Канонические 1024 FFT-бина выводятся без интерполяционной пелены при DPR 1/2/3; умножение FFT-разрешения на DPR не используется.

Точность VFO, частотная модель, DSP-фильтры и `public/audio-worklet.js` не менялись.

Проверки перед публикацией: 73 unit-теста; production build; `verify:controls`, `verify:gestures`, `verify:pwa`; `verify:regressions` со всеми уровнями S-meter на 360/390/768/1440 px; `verify:scroll` на 360×800 DPR2, 390×844 DPR3 и 1440×1000 DPR1. Сдвиг геометрии S-meter — 0 px. Проверены реальные нативные свайпы и отсутствие поздней настройки после отменённого жеста, обычное колесо на сфокусированном waterfall, Ctrl+колесо и pinch в обоих направлениях.

Переходы 40→20→15→20 м проверяются на реальных Kiwi PCM/WF. `verify:20m` по умолчанию оставляет 14.200 MHz включёнными 600 секунд и сохраняет 61 снимок метрик: медианную яркость фона, серую пелену, шумовой порог, непрозрачность, CSS, DPR, поступление данных, закрытия сокетов и реальный аудиовыход. Это клиентская проверка отображения, не измерение общей задержки радиоприёма.

```sh
TEST_APP_URL=https://web-sdr.vercel.app TEST_ARTIFACT_DIR=artifacts/20m-production npm run verify:20m
TEST_APP_URL=https://web-sdr.vercel.app TEST_ARTIFACT_DIR=artifacts/scroll-production npm run verify:scroll
TEST_APP_URL=https://web-sdr.vercel.app TEST_ARTIFACT_DIR=artifacts/meter-production npm run verify:regressions
```

Локальные и production-скриншоты и JSON-результаты сохраняются в ignored `artifacts/`.

Дополнительная проверка DPR выявила оставшийся мобильный `min-height: 240px`, который перекрывал `height: 100%` при контейнере 220 px. Он явно отменён (`min-height: 0; max-height: 100%`). Теперь `verify:scroll` и `verify:20m` сравнивают фактическую высоту canvas с контейнером. Для `verify:20m` доступны `TEST_WIDTH`, `TEST_HEIGHT` и `TEST_DPR`; мобильные переходы диапазонов проверены при 390×844/DPR3.

Финальная production-проверка 2026-10-15: версия `230b1618b038d158ed390962b89f1aa2d9d9c1ca`, 390×844/DPR3, 09:34:20–09:44:21 UTC. Переходы 40→20→15→20 м и полные 600 секунд на 20 м прошли. 61 замер: медианная яркость 22.63–36.74 из 255, доля серой пелены 0, alpha 255, закрытий WebSocket 0, ошибок страницы 0.
