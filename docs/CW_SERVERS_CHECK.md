# CW transcript, timing and receiver recovery — local stage, 2026-10-22

No publication, commit, dependency installation or interface redesign. Three focused verification groups; no mass suite.

## Causes and changes

CW text was truncated to12000 characters and the textarea was read-only. It now retains the last50000 characters without stopping PCM processing. It scrolls on arriving output, COPY reads the latest entire retained decoder text, CLEAR resets text/unfinished symbols without turning decoding off, and the textarea accepts selection, deletion and edits. UI polls pause text replacement while the user has an active selection; PCM processing continues. Revision/head-offset tracking merges edits with characters decoded since the previous UI poll, even when the rolling limit discarded old leading characters. Manual edits preserve their scroll position; receiving resumes automatic downward scroll. OFF/close still stop the consumer.

AUTO WPM previously relied on a long accumulated timing window, delaying speed changes. A change is now reacquired only when12 recent marks consistently fit a materially different unit, contain both dots/dashes and have sufficient signal quality. Otherwise the stable longer estimator is retained. A stale strong-signal peak releases faster only when a credible weaker tone is present during key-up, with the existing noise/SNR guard and envelope hysteresis preserved. No dictionary, callsign correction or synthetic transcript added.

Receiver recovery previously ignored some nonretryable badp refusals, could automatically select a different public receiver, and reset the retry counter after a short healthy interval. Automatic receiver selection is removed. Terminal access/quota refusals stop recovery. At most5 automatic reconnects are allowed per explicitly started session, including across short healthy intervals; waking a page cannot bypass an already pending retry or reset its budget. Manual start/switch establishes a new budget. Keepalive already sends once per second to both Kiwi streams; no proven keepalive parser error was found, so KiwiProtocol/WebSocket and audio code were not changed.
