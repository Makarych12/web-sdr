# Валкодеры и стабильный S-meter

Восстановлены оба прежних элемента из версии до удаления валкодеров (`0f8d858`): основной `VfoDial` в панели частоты и `FineTune` со вторым валкодером под waterfall. Их оформление и адаптивные размеры взяты из сохранившегося `console.css`. Удалены только переопределения сетки, которые добавлялись для интерфейса без валкодеров.

Оба компонента получают `frequencyHz` и `stepHz` как целые герцы из единого состояния App. Они передают изменение обратно существующей функции настройки; собственных значений частоты в state нет. Перевод в кГц остаётся на границе существующего tune/протокола. Повороты суммируют целые шаги через rAF, окончание жеста синхронно применяет остаток и отправляет последнюю команду. Сохранены прежняя анимация, захват указателя, колесо, клавиатура и touch. USB/LSB при смене режима сохраняют новый автоматический шаг 10 Гц.

S-meter получил фиксированную высоту (88 px на ширинах до 820 px, 76 px на desktop), фиксированные строки и колонки. Для S-значения выделено 8ch, для dBm — 13ch; переносы запрещены, цифры табличные. Текст уровня и доступное описание используют одинаковое округление до отображаемой десятой dBm, поэтому погрешность сглаживания около границы S9 не показывает S8 рядом с −73.0 dBm. RSSI, сглаживание и заполнение шкалы продолжают поступать из прежнего тракта.

Файлы приложения: `src/main.tsx`, `src/VfoDial.tsx`, `src/FineTune.tsx`, `src/SMeter.tsx`, `src/features.css`. Аудиобуфер, протокол Kiwi, направленные фильтры, пресеты и история waterfall не менялись.

## Проверки перед публикацией

- `npm test`: **73/73**.
- `npm run build`: успешно.
- `verify:controls`, `verify:gestures`, `verify:pwa`: успешно; управление spectrum, история, фильтр, восстановление и PWA сохранены.
- `verify:regressions`: оба валкодера на 360/390/768/1440 px; основной имеет прежние 84/98/140/164 px, второй — 86 px. Проверены шаги 1/10/100/1000 Гц, клавиатура, колесо, мышь и настоящие CDP touch-жесты. Дополнительно проверены остальные шаги и вращение через границу ±180° в обе стороны.
- `verify:dials-live`: реальный прямой WSS Niendorf на 390/1440 px. Оба валкодера с шагами 1/10/100/1000 Гц совпадают с крупным индикатором, полем и маркером; проверяются реальные отправленные `SET mod=usb low_cut=300 high_cut=2700 freq=…`. После настройки остаются один AudioContext и два Kiwi-сокета.

Для S-meter `verify:regressions` подаёт тестовые уровни через изолированный gateway fixture браузера. В код приложения тестовые сигналы не добавлены. Проверяются отсутствие сигнала, S1, S5, S9, S9 +10/+20/+60, −84.4 dBm и значения по обе стороны границ S5/S9/+. Для каждого уровня сравниваются координаты и размеры контейнера приёмника, текста, шкалы, подписей, waterfall и точной подстройки. **Смещение на всех четырёх ширинах — 0 px**. Проверены возврат к отсутствию сигнала и отсутствие горизонтального переполнения.

40 последовательных скриншотов и полный отчёт: `artifacts/receiver-regressions/`. Например, `meter-390-S1.png`, `meter-390-S5.png`, `meter-390-S9.png`, `meter-390-S9__20.png`, `meter-390-S9__60.png`. Изображения создаются тестом и не добавляются в git. Краткие результаты сохранены в `docs/dial-meter-validation.json`.

Для повторной проверки production:

```sh
TEST_APP_URL=https://web-sdr.vercel.app TEST_ARTIFACT_DIR=artifacts/receiver-regressions-production npm run verify:regressions
TEST_APP_URL=https://web-sdr.vercel.app TEST_REPORT=artifacts/dials-live-production.json npm run verify:dials-live
```
