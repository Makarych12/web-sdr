# Spectrum / waterfall / CW decoder: local verification, 2026-10-22

No commit, push or deployment. Only renderer, CW decoder/panel and focused tests changed.

## Causes established before editing

- KiwiProtocol emits real 1024-bin uncompressed W/F rows, source view/sequence and real signed 16-bit PCM. main.tsx converts PCM before transfer to the player and passes the reported sample rate to CW. No random data source or DX-driven spectral modification was found. No proven protocol error: KiwiProtocol and WebSocket are unchanged.
- The spectrum drew every instantaneous FFT row without temporal smoothing. Its input also passed through an isolated-bin limiter, altering actual narrow peaks. Removed this limiter from the active rendering path (its old exported helper remains for compatibility).
- CW searched only the manually selected tone, initially 700Hz. The existing receiver CW mode produces approximately 600Hz when centered; arbitrary SSB tuning can give other pitches. The old decoder produced an empty transcript at 700Hz on both real archived recordings. AUTO TONE was absent. Confidence required already-decoded characters and hid early acquisition quality.

## Changes

Spectrum: independent per-bin exponential smoothing in the dB byte domain, 35ms rise / 280ms fall. Only accepted new FFT rows advance the envelope; no free-running decay animation. Reset envelope on view changes so unrelated frequencies cannot share state. Waterfall receives original copied bins, retains original row normalization, LUT themes, scrolling and historical projection. Frequency coordinates remain header start + bin/1024 * span. DX overlays untouched.

CW: AUTO TONE defaults ON, searches 300–1000Hz in Hann-windowed 40ms PCM blocks, 25Hz bank with sub-bin interpolation. Requires repeated narrow spectral evidence and holds lock through ordinary key-up gaps. Manual tone remains available by disabling AUTO TONE; default manual pitch is 600Hz. Existing hysteretic envelope and keyed timing/speed estimator now operate at the acquired tone, at the actual PCM rate. Confidence can report acquisition before the first decoded letter, but text still requires signal/rhythm evidence and acquisition marks; no dictionary or callsign completion. Oversized invalid patterns do not inject unconditional replacement characters into silence/noise. UI shows acquired tone, selected-tone dBFS level, actual PCM sample rate/count and processing state. Closing removes the PCM consumer and UI polling.

## Reproduction and limits

Artifacts: artifacts/spectrum-cw-fix/{live.json,live-fft.json,live-cw.f32,live.png,fft.json,real.json,timing.log,performance.json,tone-reference.json}. Local harnesses live.mjs, fft.mjs, real.mts, performance.mjs, tone-reference.mjs are in that folder; they use already-installed Chrome, Node/tsx and Playwright, not new dependencies. Live source selection is based on real incoming bins, not a preassigned transcript. HMR can load timestamped module instances: instrumentation must use the actual loaded module URL or a fresh Vite process.

Archived recordings retain the provenance in CW_DECODER.md: real author-posted off-air recordings from archive.org; neither they nor their outputs are shipped as demo data. No human-verified transcript is available. AUTO TONE can choose another narrow signal in a crowded passband; use manual tone and a narrower existing receiver filter. Hand keying, fading, overlapping stations and very weak CW remain error-prone. Leading characters during speed/tone acquisition can be lost. Closing stops all decoder computation; radio transport/playback keep their existing lifecycle.

Changed production files: src/spectrumRenderer.ts, src/cwDecoder.ts, src/CwDecoderPanel.tsx. Existing PCM dispatch, player, NR, NOTCH, EQ, REC, SCAN, MEM, LOGBOOK, DX Cluster and theme definitions were not edited.
