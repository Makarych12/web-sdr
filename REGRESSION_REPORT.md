# Исправление регрессии WebSDR — 2026-10-11

## История и причина

Изучены последние коммиты и diff `3283b7e..2944b88`. Основа восстановления — `3283b7e`: последний коммит перед фоновыми экспериментами, уже содержащий дизайн Malachite, улучшенную панораму/waterfall, VFO, мобильную адаптацию и QuickTune.

- `9f7aff5`: вывод AudioWorklet перенаправлен через MediaStreamAudioDestinationNode и постоянный HTMLAudioElement; добавлены Media Session и фоновый lifecycle.
- `4fe59c3`: дополнительный HTTP MP3-сеанс Kiwi и tune через HTTP с объединением событий на 180 мс. PCM обычного сеанса продолжал приходить, хотя его вывод отключался. Это добавляло канал Kiwi, кодирование и буфер медиаплеера.
- `2944b88`: HLS-сегменты, ffmpeg, дополнительные маршруты и серверные сеансы для фона.

180 мс задержки HTTP-команд и буферизация MP3/HLS подтверждены кодом. Точный вклад каждого изменения в субъективную задержку звука отдельно не измерялся. Media Session сама по себе не признана доказанной причиной задержки.

В локальных и remote-tracking ветках найдена только `main`. Отдельного нового gateway-хоста или новой env-переменной после `3283b7e` не найдено: эксперимент был дополнительным аудиосервисом внутри того же gateway. Основной gateway не удалён.

## Изменения

Восстановлены обычный AudioContext → AudioWorklet → GainNode → AudioContext.destination и прежнее подключение через один production gateway собственного origin. Сохранён существовавший до регрессии прямой WSS к HTTPS Kiwi.

Удалены `server/nativeAudio.js`, `server/hlsAudio.js`, `server/hlsEncoder.js`, `/api/audio*`, `/api/hls*`, MediaStream/HTMLAudioElement, Media Session, фоновая панель, диагностика и отдельный audio-check. Удалены фоновые тесты, ffmpeg/lamejs/@vercel/functions и конфигурация упаковки/маршрутизации HLS. Service worker cache обновлён до v12. Новые серверы и прокси не добавлены.

CSS дизайна, VFO, FineTune, QuickTune, цифровая частота, фильтры, AGC, диапазоны и улучшенный renderer сохранены. Основной React-компонент восстановлен выборочно из указанной версии, затем дополнен защитами и быстрым tune. Git reset не применялся.

- Throttle tune — 40 мс; хранится одна ожидающая отправка, которая читает последние настройки. При отпускании VFO flushTune отменяет таймер и отправляет последнюю позицию синхронно.
- Диапазоны, режимы, filter и AGC отправляют команду сразу. Они не пересоздают подключение. UI частоты/маркера обновляется синхронно даже из native wheel-события; старое tuned не меняет частоту.
- RF tune/смена режима или фильтра очищает PCM. Смена сервера/переподключение также очищает очередь. Zoom/pan сохраняют аудиограф и очередь.
- PCM startup buffer — 200 мс, адаптация после underflow до 350 мс; верхняя граница очереди — 750 мс. При переполнении выбрасываются старые пакеты до примерно 300 мс, включая случай одного слишком большого пакета. Reset возвращает стартовый запас к 200 мс.
- Сохранён generation ID клиента. У закрытого KiwiProtocol parse/apply игнорируются; серверный generation отменяет отложенный connect. Stop отменяет tune/reconnect/watchdog. Асинхронный запуск аудио имеет свой generation.
- pageshow/visibilitychange возобновляют AudioContext и проверяют текущий WebSocket. Свежий сеанс сохраняется; ручной stop не отменяется. Обещаний работы при выключенном экране нет.

## Проверки и измерения

Проверена локальная исправленная production-сборка на настоящих публичных Kiwi Niendorf и ZL2P. Gateway и прямой WSS проверены браузерными тестами. Это Chromium, включая эмуляцию touch и viewport; физические телефоны и выключенный экран не тестировались. Исправление не опубликовано в Vercel.

- `npm test`: 40/40.
- `npm run build`: успешно.
- `npm run verify:browser`: успешно, настоящий ненулевой выход AudioWorklet, tune, WF и forced reconnect.
- `TEST_RECEIVER=niendorf TEST_GATEWAY=1 TEST_SECOND_RECEIVER=zl2p npm run verify:sdr`: успешно. Все девять диапазонов, AM/USB/LSB/CW/FM, фильтр, AGC, быстрый VFO, mouse/touch/pinch, zoom/pan, смена серверов, stop/restart, избранное, 320/390/820/1440 px; pageErrors отсутствуют.
- `TEST_RECEIVER=niendorf TEST_FILTERS=1 TEST_PAN=1 TEST_WATERFALL=1 npm run verify:live`: 34 настоящих потоковых этапа, PCM записан в WAV.
- `npm run verify:latency`: 40 проверок с performance.now; шаги 1/10/100/1000/5000/10000 Hz в обе стороны, UI проверяется после каждого wheel-события и на ближайшем кадре, последняя tune-команда и отсутствие очереди после release, stop/restart, две смены реального Kiwi, recovery без дублей, mobile.

Последний latency-прогон:

| Измерение | Время |
| --- | ---: |
| VFO событие → цифровая частота, максимум на событие | 2.8 мс |
| VFO burst → последняя отправка tune, максимум | 78.3 мс |
| Диапазон/режим/filter → отправка tune, максимум | 4.2 мс |
| Отпускание VFO → flushTune | 0.4 мс |
| Stop → вызов close старого WebSocket | 0.3 мс |
| Повторное включение → создание WebSocket | 0.7 мс |
| Повторное включение → первый PCM / WF | 680.5 / 538.3 мс |

Время close выше измеряет вызов закрытия; завершение сетевого handshake зависит от транспорта.

Через gateway в браузере активен **один `/ws`**, а gateway открывает два необходимых канала Kiwi: **SND + W/F**, в рамках одного сеанса. При прямом WSS браузер открывает ровно эти два канала. Дополнительного канала для фонового звука нет. Тест проверяет один активный gateway WebSocket после restart и каждой смены сервера, и отсутствие новых соединений от pageshow/visibilitychange или после stop.

Ненулевой реальный звук и актуальная частота/spectrum/waterfall подтверждены. Старые PCM удаляются reset и ограничением очереди; старые tune не проигрываются после release. Полная задержка RF → физический динамик не измерялась.

Публичные Kiwi иногда не отвечали на handshake: France недоступен; у Niendorf встречались SND/WF handshake timeout 10 секунд с последующим успешным retry. В последнем latency-прогоне первое WF пришло через 12,46 секунды из-за такого timeout; повторное включение дало WF за 538,3 мс. Поэтому мгновенный сетевой запуск любого публичного узла не обещается. Локальный connect и ручная смена сервера начинают открытие сразу, без ожидания таймера прошлого сеанса.
