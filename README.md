# UR4MTN WEB SDR

Рабочий HF-приёмник: React + TypeScript, Node.js WebSocket-шлюз, реальный PCM-звук и spectrum/waterfall KiwiSDR. Адаптивный интерфейс и PWA. Имитации сигнала нет.

## Production: Vercel Hobby

Frontend и Node.js KiwiSDR gateway размещаются в одном Vercel-проекте. `api/gateway.js` экспортирует HTTP server с WebSocket Upgrade; `/ws` и API направляются в эту функцию. Браузер использует свой origin для HTTPS API и проксируемого WSS. Для публичных Kiwi с HTTPS он подключает два WSS-канала напрямую: звук и waterfall. Протокол общий для браузерного клиента и шлюза. Render, Railway, VPS и `VITE_GATEWAY_URL` не нужны.

Включите Fluid compute в настройках проекта. WebSocket beta доступна на Hobby; действуют бесплатные квоты Vercel, не безлимитный трафик. Прямые соединения с HTTPS Kiwi не зависят от длительности функции Vercel. Для HTTP Kiwi функция шлюза ограничена 300 секундами: клиент автоматически переподключается и восстанавливает выбранный KiwiSDR, частоту, режим, фильтр и waterfall. Каталог хранится в памяти и `/tmp`, постоянная база не требуется. Свежий снимок `server/catalog-seed.json` входит в деплой: при таймауте публичного источника полный список остаётся доступен, `/api/catalog` честно сообщает `stale: true`.

```sh
npx vercel --prod
TEST_URL=wss://web-sdr.vercel.app/ws npm run verify:live
TEST_APP_URL=https://web-sdr.vercel.app npm run verify:production
```


Откройте http://localhost:5173. Для готовой сборки:

```sh

```

Адрес: http://localhost:8787. Кнопка «Слушать эфир» запускает звук после пользовательского нажатия. Для телефона или планшета через сеть нужен HTTPS: AudioWorklet, service worker и установка PWA доступны в безопасном контексте. HTTPS reverse proxy должен передавать Host и поддерживать WebSocket Upgrade. Без сети доступен сохранённый интерфейс; радиоприём требует работающего шлюза и интернета.

## Управление

- **Приёмники:** кнопка «Приёмник» или меню «Серверы», открывающие одно и то же окно с поиском по названию, месту и позывному. В каталоге около 850–900 публичных KiwiSDR; количество зависит от обновления. Выбор другого узла во время приёма закрывает предыдущий сеанс и запускает новый с текущей частотой, режимом, фильтром и видом waterfall.
- **Избранное:** ★ рядом с сервером, ☆ «Сохранить» рядом с частотой. В памяти частоты сохраняются режим и ширина фильтра. Избранное, выбранный сервер, громкость, mute, полосы по режимам и шаг настройки хранятся локально в браузере и сохраняются после перезагрузки. × удаляет частоту из избранного.
- **Частота:** ввод в kHz и Enter/↵; кнопки ± и шаг 10 Hz…10 kHz; касание или перетаскивание по spectrum/waterfall в режиме ☝. При перетаскивании частоты вид остаётся на месте, чтобы сигнал не уходил из-под пальца.
- **Режимы:** AM, USB, LSB, CW и узкополосная FM. FM работает в HF-диапазоне KiwiSDR; это не FM-вещание 88–108 MHz.
- **Фильтр:** «Полоса фильтра» меняет реальный DSP-фильтр KiwiSDR. USB/LSB сохраняют правильную боковую полосу; CW центрируется на 600 Hz. Зелёная область на спектре показывает полосу приёма.
- **S-meter:** реальные RSSI-пакеты KiwiSDR, шкала S1–S9/+dB и dBm, быстрый рост, плавное спадание, удержание пика. HF-шкала использует S9 = −73 dBm и 6 dB на S-единицу, согласно [IARU Region 1, Technical Recommendation R.1](https://www.iaru-r1.org/wp-content/uploads/2021/03/VHF_Handbook_V9.01.pdf). Точность абсолютного уровня зависит от калибровки удалённого приёмника.
- **Громкость:** плавный GainNode и mute, независимые от демодуляции и RF-уровня. На телефоне регулятор находится в потоке страницы и не перекрывает остальные элементы.
- **Waterfall:** +/− до zoom 14 (в пределах возможностей сервера), стрелки панорамы, ↔ и перетаскивание, «К частоте». Два пальца меняют zoom и панораму; колесо мыши масштабирует вокруг курсора, Shift+колесо панорамирует. Pan/zoom не меняют частоту приёма и не сбрасывают аудиоочередь. При изменении диапазона история сохраняется и проецируется в новые частотные координаты. Реальный предел zoom учитывает и zoom_max, и zoom_cap приёмника.
- **Клавиатура:** на сфокусированном canvas ←/→ меняют частоту на выбранный шаг (Shift — ×10), +/− меняют масштаб.
- **Переподключение:** при разрыве или зависании потока приложение автоматически восстанавливает сеанс с последними настройками, используя экспоненциальные задержки около 1–30 секунд и небольшой jitter. Для занятого сервера минимальная задержка 15 секунд. «Повторить сейчас» ускоряет новую попытку; «Отключиться» отменяет все попытки и освобождает канал. Сначала приложение повторяет подключение к текущему узлу. Только повторный подтверждённый отказ либо несколько ошибок upstream допускают другой публичный KiwiSDR (не более пяти альтернатив за запуск). Обычный транспортный разрыв не переключает приёмник. Текущий узел и причина восстановления/смены видны в интерфейсе. Ограничения IP/времени останавливают повторные подключения. При блокировке звука мобильным браузером появляется «Возобновить звук».

## Публичный каталог

Источник: [публичный каталог KiwiSDR](http://kiwisdr.com/public/), машиночитаемый снимок [rx.linkfanel.net](http://rx.linkfanel.net/kiwisdr_com.js). Шлюз обновляет его каждые 15 минут и сохраняет последний удачный снимок в `.cache/catalog.json` локально и `/tmp/ur4mtn/catalog.json` на Vercel. Занятость/SNR в списке относятся к каталогу и не являются гарантией свободного канала. В `/api/catalog` доступны время обновления и флаг `stale`.

`server/receivers.json` содержит начальные/закреплённые серверы: они остаются доступными при недоступности каталога. Фронтенд отправляет только идентификатор сервера. Каталог разбирается как JSON5-данные без выполнения JavaScript. Приватные/локальные адреса отсекаются, DNS при подключении проверяется, произвольные URL пользователя не принимаются.

Публичные узлы иногда заняты, отключены или ограничивают API. В этом случае выберите другой приёмник. Шлюз предназначен для локального использования; публикация для многих пользователей требует аутентификации и ограничения числа сеансов.

## Протокол

Проверен по исходникам:

- [KiwiClient client.py](https://github.com/jks-prv/kiwiclient/blob/master/kiwi/client.py), исходный commit `4eb733e6b6147f7fbeb97ced64cdac029b202d18`.
- [KiwiSDR kiwi_util.js](https://github.com/jks-prv/KiwiSDR/blob/master/web/kiwi/kiwi_util.js), [rx_server.cpp](https://github.com/jks-prv/KiwiSDR/blob/master/rx/rx_server.cpp), [rx_waterfall.cpp](https://github.com/jks-prv/KiwiSDR/blob/master/rx/rx_waterfall.cpp). Исходный проверенный commit `3b570602a14161188f8c85eede62ab2a70e7ad66`.

Upstream: `/ws/kiwi/<timestamp>/SND` и `/ws/kiwi/<timestamp>/W/F`, одна сессия с общим уникальным timestamp. `SET auth t=kiwi p=`, согласование `audio_rate`/`AR OK`, настройка после `sample_rate`/`wf_setup`, keepalive раз в секунду. PCM и waterfall передаются без компрессии.

`SND`: tag (3), flags (1), sequence LE (4), RSSI BE (2), mono PCM signed 16-bit BE. `W/F`: tag (3), pad (1), start bin LE (4), flags/zoom LE (4), sequence LE (4), 1024 unsigned bins. Калибровка waterfall и bandwidth берутся у сервера. PCM воспроизводится через AudioWorklet с интерполяцией реальной входной частоты дискретизации и ограничением очереди.

Downstream `/ws`: `connect` с `receiver`, `frequency` (kHz), `mode`, `zoom`; `tune` с теми же полями без receiver; `disconnect`. Опциональные `lowCut`/`highCut` в Hz, `viewCenter` в kHz, `agc` (`slow` / `fast` / `off`). AGC отправляется реальной командой Kiwi; изменение AGC не пересоздаёт звук или waterfall. Старые команды без новых полей продолжают работать. Частые команды жестов объединяются в клиенте; при изменении только вида шлюз отправляет только `SET zoom=... cf=...`. Binary: байт 1 + PCM BE, байт 2 + waterfall bins. JSON: sample rate, RSSI, calibration, actual view (start/span/zoom/bandwidth), tuned, limits, errors с `code`/`retryable`. `tuned` подтверждает отправку команды; live-тесты отдельно проверяют реальные частотные границы возвращённого waterfall.

## Интерфейс UR4MTN

Компактная CSS/SVG hero-секция, крупный позывной и кнопка запуска реального приёмника. Цифровая частота в Hz, вращаемый VFO (мышь/палец/клавиатура), шаги 1/10/100/1000/5000/10000 Hz, AGC и диапазоны 160–10m. Частотная шкала реагирует на tap/drag. Оригинальная QSL скопирована без изменений из загруженного ur4mtn.jpg; используется в preview и «О проекте». Анимации учитывают prefers-reduced-motion. Верхнее меню ведёт к приёмнику, каталогу серверов, избранному и описанию проекта. При прокрутке звук и canvas остаются активными. Популярные диапазоны настраивают частоту и открывают приёмник. Существующие ключи хранения избранного и настроек сохранены.

`npm run verify:ui` проверяет навигацию, каталог и отсутствие горизонтального переполнения на 320/390/820/1440 px; снимки — `artifacts/ur4mtn-*-home.png` и `artifacts/ur4mtn-*-studio.png`. `verify:sdr` запускает эфир через hero-кнопку и проверяет реальный звук, частоту и waterfall после каждой операции.

## Фоновый эфир и сон телефона

Постоянный аудиотракт: Kiwi PCM → AudioWorklet → GainNode → MediaStreamAudioDestinationNode → HTMLAudioElement. Элемент `<audio autoplay playsinline>` остаётся в документе и использует один MediaStream между настройками частоты и переподключениями. Громкость и mute применяются в GainNode. При поддержке `navigator.audioSession` выбирается категория `playback`.

«Фоновый эфир» включён по умолчанию. В скрытой вкладке PCM продолжает поступать в AudioWorklet, renderer прекращает рисование и не копит строки waterfall. После возвращения история начинается с новых реальных данных. Если фоновый режим выключен, скрытие приостанавливает локальный звук, возвращение возобновляет его.

Media Session показывает UR4MTN WEB SDR, частоту, режим и приёмник. Play запускает/возобновляет эфир; pause и stop отключают приём, сохраняя настройки и аудиограф для следующего play. При `visibilitychange`, `pageshow`, `resume` и возвращении сети проверяются выход и свежесть PCM. Исправный WebSocket сохраняется; оборванный или давно не получающий PCM восстанавливается существующим механизмом. В `sessionStorage` сохраняются частота, режим, фильтр, AGC, zoom, центр, сервер и намерение продолжать эфир. После перезагрузки вкладки приложение пытается восстановиться; если autoplay запрещён, показывает «Возобновить звук». Явное отключение отменяет восстановление.

«Оставлять экран включённым» — отдельный, выключенный по умолчанию Screen Wake Lock: только при запущенном эфире и видимой странице. Это удобство просмотра, а не средство фонового воспроизведения. Manifest уже содержит `display: standalone`. Service worker кеширует оболочку; WebSocket и аудиосеанс остаются в странице.

ОС может выгрузить страницу и остановить JavaScript, WebSocket и аудио, особенно на iOS. Эти ограничения нельзя отменить веб-кодом. Для конкретного устройства необходимо проверить установленную PWA и обычную вкладку: запустить реальный эфир, подключить Bluetooth-наушники, заблокировать экран на 2–5 минут, проверить непрерывность/восстановление, кнопки play/pause гарнитуры и экрана блокировки.
