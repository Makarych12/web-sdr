# UR4MTN WEB SDR

Рабочий HF-приёмник: React + TypeScript, Node.js WebSocket-шлюз, реальный PCM-звук и spectrum/waterfall KiwiSDR. Адаптивный интерфейс и PWA. Имитации сигнала нет.

## Production: Vercel + Render

Фронтенд на Vercel использует внешний Node gateway на Render. Инструкция по полям панели, env и проверке: [DEPLOY_RENDER.md](./DEPLOY_RENDER.md). Dockerfile запускает только шлюз; frontend build остаётся на Vercel. `VITE_GATEWAY_URL` — публичный HTTPS origin Render, `ALLOWED_ORIGINS` — точный origin Vercel. Production сборка не принимает localhost backend. Vite proxy работает исключительно в локальном dev-сервере.

## Запуск

Node.js 20.19+ или 22.12+.

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Для готовой сборки:

```sh
npm run build
npm start
```

Адрес: http://localhost:8787. Кнопка «Слушать эфир» запускает звук после пользовательского нажатия. Для телефона или планшета через сеть нужен HTTPS: AudioWorklet, service worker и установка PWA доступны в безопасном контексте. HTTPS reverse proxy должен передавать Host и поддерживать WebSocket Upgrade. Без сети доступен сохранённый интерфейс; радиоприём требует работающего шлюза и интернета.

## Управление

- **Приёмники:** выпадающий список или «Все приёмники» с поиском по названию, месту и позывному. В каталоге около 850–900 публичных KiwiSDR; количество зависит от обновления. Выбор другого узла во время приёма закрывает предыдущий сеанс и запускает новый с текущей частотой, режимом, фильтром и видом waterfall.
- **Избранное:** ★ рядом с сервером, ☆ «Сохранить» рядом с частотой. В памяти частоты сохраняются режим и ширина фильтра. Избранное, выбранный сервер, громкость, mute, полосы по режимам и шаг настройки хранятся локально в браузере и сохраняются после перезагрузки. × удаляет частоту из избранного.
- **Частота:** ввод в kHz и Enter/↵; кнопки ± и шаг 10 Hz…10 kHz; касание или перетаскивание по spectrum/waterfall в режиме ☝. При перетаскивании частоты вид остаётся на месте, чтобы сигнал не уходил из-под пальца.
- **Режимы:** AM, USB, LSB, CW и узкополосная FM. FM работает в HF-диапазоне KiwiSDR; это не FM-вещание 88–108 MHz.
- **Фильтр:** «Полоса фильтра» меняет реальный DSP-фильтр KiwiSDR. USB/LSB сохраняют правильную боковую полосу; CW центрируется на 600 Hz. Зелёная область на спектре показывает полосу приёма.
- **S-meter:** реальные RSSI-пакеты KiwiSDR, шкала S1–S9/+dB и dBm, быстрый рост, плавное спадание, удержание пика. HF-шкала использует S9 = −73 dBm и 6 dB на S-единицу, согласно [IARU Region 1, Technical Recommendation R.1](https://www.iaru-r1.org/wp-content/uploads/2021/03/VHF_Handbook_V9.01.pdf). Точность абсолютного уровня зависит от калибровки удалённого приёмника.
- **Громкость:** плавный GainNode и mute, независимые от демодуляции и RF-уровня. На телефоне панель громкости всегда доступна снизу.
- **Waterfall:** +/− до zoom 14 (в пределах возможностей сервера), стрелки панорамы, ↔ и перетаскивание, «К частоте». Два пальца меняют zoom и панораму; колесо мыши масштабирует вокруг курсора, Shift+колесо панорамирует. Pan/zoom не меняют частоту приёма и не сбрасывают аудиоочередь. При изменении диапазона история waterfall очищается, чтобы старые строки не показывались под новой шкалой.
- **Клавиатура:** на сфокусированном canvas ←/→ меняют частоту на выбранный шаг (Shift — ×10), +/− меняют масштаб.
- **Переподключение:** при разрыве или зависании потока приложение автоматически восстанавливает сеанс с последними настройками, используя экспоненциальные задержки около 1–30 секунд и небольшой jitter. Для занятого сервера минимальная задержка 15 секунд. «Повторить сейчас» ускоряет новую попытку; «Отключиться» отменяет все попытки и освобождает канал. Пароль и ограничения IP/времени останавливают повторные подключения. При блокировке звука мобильным браузером появляется «Возобновить звук».

## Публичный каталог

Источник: [публичный каталог KiwiSDR](http://kiwisdr.com/public/), машиночитаемый снимок [rx.linkfanel.net](http://rx.linkfanel.net/kiwisdr_com.js). Шлюз обновляет его каждые 15 минут и сохраняет последний удачный снимок в `.cache/catalog.json`. Занятость/SNR в списке относятся к каталогу и не являются гарантией свободного канала. В `/api/catalog` доступны время обновления и флаг `stale`.

`server/receivers.json` содержит начальные/закреплённые серверы: они остаются доступными при недоступности каталога. Фронтенд отправляет только идентификатор сервера. Каталог разбирается как JSON5-данные без выполнения JavaScript. Приватные/локальные адреса отсекаются, DNS при подключении проверяется, произвольные URL пользователя не принимаются.

Публичные узлы иногда заняты, отключены или ограничивают API. В этом случае выберите другой приёмник. Шлюз предназначен для локального использования; публикация для многих пользователей требует аутентификации и ограничения числа сеансов.

## Протокол

Проверен по исходникам:

- [KiwiClient client.py](https://github.com/jks-prv/kiwiclient/blob/master/kiwi/client.py), исходный commit `4eb733e6b6147f7fbeb97ced64cdac029b202d18`.
- [KiwiSDR kiwi_util.js](https://github.com/jks-prv/KiwiSDR/blob/master/web/kiwi/kiwi_util.js), [rx_server.cpp](https://github.com/jks-prv/KiwiSDR/blob/master/rx/rx_server.cpp), [rx_waterfall.cpp](https://github.com/jks-prv/KiwiSDR/blob/master/rx/rx_waterfall.cpp). Исходный проверенный commit `3b570602a14161188f8c85eede62ab2a70e7ad66`.

Upstream: `/ws/kiwi/<timestamp>/SND` и `/ws/kiwi/<timestamp>/W/F`, одна сессия с общим уникальным timestamp. `SET auth t=kiwi p=`, согласование `audio_rate`/`AR OK`, настройка после `sample_rate`/`wf_setup`, keepalive раз в секунду. PCM и waterfall передаются без компрессии.

`SND`: tag (3), flags (1), sequence LE (4), RSSI BE (2), mono PCM signed 16-bit BE. `W/F`: tag (3), pad (1), start bin LE (4), flags/zoom LE (4), sequence LE (4), 1024 unsigned bins. Калибровка waterfall и bandwidth берутся у сервера. PCM воспроизводится через AudioWorklet с интерполяцией реальной входной частоты дискретизации и ограничением очереди.

Downstream `/ws`: `connect` с `receiver`, `frequency` (kHz), `mode`, `zoom`; `tune` с теми же полями без receiver; `disconnect`. Опциональные `lowCut`/`highCut` в Hz, `viewCenter` в kHz, `agc` (`slow` / `fast` / `off`). AGC отправляется реальной командой Kiwi; изменение AGC не пересоздаёт звук или waterfall. Старые команды без новых полей продолжают работать. Частые команды жестов объединяются в клиенте; при изменении только вида шлюз отправляет только `SET zoom=... cf=...`. Binary: байт 1 + PCM BE, байт 2 + waterfall bins. JSON: sample rate, RSSI, calibration, actual view (start/span/zoom/bandwidth), tuned, limits, errors с `code`/`retryable`. `tuned` подтверждает отправку команды; live-тесты отдельно проверяют реальные частотные границы возвращённого waterfall.

## Проверки

```sh
npm test
npm run build
# В другом терминале уже должен работать npm start:
npm run verify:live
TEST_FILTERS=1 TEST_PAN=1 npm run verify:live
npm run verify:browser
npm run verify:sdr
npm run verify:pwa
npm run verify:split
```

Live-проверки используют реальные публичные каналы: запускайте их последовательно. Сменить тестовый узел: `TEST_RECEIVER=<id>`. Для проверки переключения двух узлов: `TEST_SECOND_RECEIVER=<id> npm run verify:sdr`; ID находятся в `/api/receivers`. Публичные узлы могут стать недоступны между запусками.

Browser-тесты используют `/usr/bin/chromium` через Playwright. `verify:sdr` проверяет поток после каждой операции: изменение частоты/режима/фильтра, gain/mute, pan/zoom, реальные браузерные touch-события, pinch, принудительный разрыв WebSocket, восстановление частоты/фильтра/вида, ручную остановку, сохранение избранного после reload. Число PCM/WF-пакетов должно увеличиваться, AudioWorklet должен выдавать ненулевые отсчёты. Проверяются ширины 320/390/820/1440 px и отсутствие ошибок страницы. Это эмуляция устройств в Chromium; физические Android/iOS-устройства отдельно не проверялись.

Проверено 2026-10-04: исходный рабочий поток, затем каталог/избранное, фильтры/S-meter, переподключение и жесты с повторными live-проверками после каждого этапа. Полный тест переключения прошёл между Montmorillon (France) и DG2SAX (Germany). Из каталога один проксируемый узел оказался недоступен, что корректно привело к повторным попыткам.

Артефакты: `artifacts/live-report.json`, `live-audio.wav`, `sdr-browser-report.json`, `sdr-phone.png`, `sdr-small-phone.png`, `sdr-tablet.png`, `sdr-desktop.png`. PWA: service worker, загрузка manifest/icons, offline shell.

## Интерфейс UR4MTN

Компактная CSS/SVG hero-секция, крупный позывной и кнопка запуска реального приёмника. Цифровая частота в Hz, вращаемый VFO (мышь/палец/клавиатура), шаги 1/10/100/1000/5000/10000 Hz, AGC и диапазоны 160–10m. Частотная шкала реагирует на tap/drag. Оригинальная QSL скопирована без изменений из загруженного ur4mtn.jpg; используется в preview и «О проекте». Анимации учитывают prefers-reduced-motion. Верхнее меню ведёт к приёмнику, каталогу серверов, избранному и описанию проекта. При прокрутке звук и canvas остаются активными. Популярные диапазоны настраивают частоту и открывают приёмник. Существующие ключи хранения избранного и настроек сохранены.

`npm run verify:ui` проверяет навигацию, каталог и отсутствие горизонтального переполнения на 320/390/820/1440 px; снимки — `artifacts/ur4mtn-*-home.png` и `artifacts/ur4mtn-*-studio.png`. `verify:sdr` запускает эфир через hero-кнопку и проверяет реальный звук, частоту и waterfall после каждой операции.

`verify:split` собирает production frontend с внешним HTTPS-origin, запускает локальный TLS edge для отдельного Node gateway и проверяет реальные HTTPS API/CORS, WSS, звук AudioWorklet, настройку частоты и waterfall. Этот тест проверяет разделённую схему, но не означает, что сервис Render уже создан. Docker-демон в среде отсутствует: сборка контейнера выполняется на Render.
